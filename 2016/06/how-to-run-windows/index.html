Как запустить Windows-сервер в OVH

June 28, 2016 - laborant

Приветствую!

Часто возникает желание запустить Windows Server на сервере в OVH, но при этом в панели управления сервером по-умолчанию можно накатить только Linux-дистрибутивы. И это в целом правильно. С нынешним уровнем производительности процессоров можно спокойно запускать ОС в виртуальной машине и практически не иметь просадок производительности.

При этом у нас появляются дополнительные плюшки - возможность поднять несколько VM на одном сервере, снапшоты, клонирование виртуалок и прочие радости.

Так как же накатить винду на сервере в OVH?

Можно конечно накатить один из популярных Linux-дистрибутивов, поставить Virsh и запустить с консоли VM, но этот путь не самый удобный. Мы воспользуемся Proxmox 4. Тем более его можно накатить прямо из панели управления сервером.

Далее получаем письмо из OVH с рутовым паролем и реквизитами для входа в панель управления Proxmox.

Краткий список шагов:

1) Заходим на сервер по SSH и скачиваем в /var/lib/vz/template/iso образ с виндой (например win2k8.iso)

2) Редактируем файл /etc/network/interfaces

Закомменчиваем

# for Routing
#auto vmbr1
#iface vmbr1 inet manual
#       post-up /etc/pve/kvm-networking.sh
#       bridge_ports dummy0
#       bridge_stp off
#       bridge_fd 0

Вставляем

auto vmbr1
iface vmbr1 inet static
        address  192.168.1.1
        netmask  255.255.255.0
        bridge_ports none
        bridge_stp off
        bridge_fd 0

post-up echo 1 > /proc/sys/net/ipv4/ip_forward
post-up iptables -t nat -A POSTROUTING -s '192.168.1.0/24' -o vmbr0 -j MASQUERADE
post-down iptables -t nat -D POSTROUTING -s '192.168.1.0/24' -o vmbr0 -j MASQUERADE

И включам форвардинг

echo 1 > /proc/sys/net/ipv4/ip_forward

3) Перезагружаем сервер командой reboot

4) Заходим в панель управления Proxmox и жмем там «Create VM» и выбираем ранее загруженный на сервер iso-файл, в настройках сети указываем bridge vmbr1, ip выбираем любой понравившийся из подсети 192.168.1.* Стартуем виртуалку и в меню «Console» выбираем noVNC.

5) Устанавливаем винду.

Опционально можно выбрать видеодрайвер SPICE (qxl) и подключаться к серверу через более производительный SPICE-протокол.
